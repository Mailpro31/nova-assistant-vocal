Data boundaries before deployment

Private by architecture.
Precise in the promise.

Nova separates what is available in the product today from what must be designed and validated for an organization deployment.

Available · Local

Processing on the PC.

Local dictation, rewriting, vocabulary and history can stay on the user’s Windows device.

  • Local transcription
  • Local rewriting option
  • Local SQLite history
  • Windows-protected secrets
Available · Turbo

Cloud by explicit choice.

Cloud features are enabled deliberately for the requested processing, with local fallback available.

  • Opt-in mode
  • Task-bound processing
  • No Nova content archive
  • Provider terms disclosed
Scoped · Organization

Private runtime discovery.

A dedicated Organization processing path is scoped with security and IT stakeholders before it is promised or deployed.

  • Architecture review
  • Data-flow documentation
  • Identity requirements
  • Pilot validation

SSO, SCIM, centralized policies and a private Organization runtime are not presented as generally available capabilities until technically validated for the deployment.

Business FAQ

What exists.
What gets scoped.

Does Nova support multi-seat licensing?+

Yes. The current Business tier supports seat-based licensing. Rollout and support requirements are reviewed during discovery.

Are SSO, SCIM and centralized policies available?+

They are not claimed as generally available today. If required, they are captured as technical requirements and must be validated before publication or rollout.

Can Nova run without cloud processing?+

Local dictation and rewriting can run on compatible Windows PCs. Cloud features such as Turbo are opt-in.

What is a private runtime discovery?+

It is a technical scoping step covering data flows, infrastructure ownership, isolation, providers and operational responsibilities before a private deployment is promised.
